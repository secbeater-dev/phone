# Single-file multi-phone streaming implementation

## Goal and constraints

Implement the approved single-file multi-phone design in the existing static website. Preserve browser-only processing and all existing supported small-file formats. New large-workbook processing must use bounded batches, a dedicated worker, and temporary IndexedDB storage; never fall back to main-thread full-workbook parsing. User selected per-session reimport, synchronized target selection across ordinary analysis/attachments, and automatic export volumes. Multi-number location stays independent. No real CDR files, contents, identifiers, screenshots, counts, or logs enter Git or external services. Read fullview.md before edits and update it for the final architecture. User authorized GitHub push and production website validation after tests.

## Architecture and acceptance

File Blob -> ZIP random access -> SAX worksheet rows -> normalized batches -> IndexedDB -> worker queries -> 500-row UI pages. At most 1,000 rows or 4 MiB per ingestion batch, shared string cache bounded to 16 MiB. One active heavy operation per page. Worker operations have request IDs, cancellation and progress; stale results never replace newer selections. Raw header aliases include underscores, hyphens, IMEI/IMSI/IP case. Source worksheets are calls, users, network; integrated history is deliberately excluded. Target precedence: query item, then per-row target/account, otherwise unassigned; never use all users as a record default. Per-target profile metadata remains separate. Records carry kind, source sheet and physical row. Invalid nonempty times retained with warnings. Temporary datasets are isolated per session, cleaned explicitly and on next startup if their owner is gone; no resume across reload. Final output creation is sequential and bounded (10,000 rows or 16 MiB per volume), all data retained. Synthetic tests exercise omissions, aliases, target scope, cancellation, cleanup, pagination, output, quota and browser races. Performance gates target <=1 GiB renderer/worker peak, <200 ms UI reaction, indexed target first page <2 s, cancellation <1 s on 4 cores/8 GiB; measure honestly and report unavailable hardware checks. Repository baseline: 24 tests pass, 2 private opt-in tests skipped.

Add UMD globals PhoneStreamingXlsx and PhoneCdrModel and CommonJS exports. Pin same-origin zip.js (no nested workers, no WASM fetch or dynamic external paths) and SAX dependencies with licenses; Node tests use local vendored files. No package build requirement at runtime.

PhoneStreamingXlsx.inspect(file, {signal}={}) => Promise<{supported, sheets:[{name,path,uncompressedSize}], estimatedBytes}>. Inspect workbook relationships via BlobReader without reading complete workbook. Supported when a worksheet named 通聯紀錄 or 網路歷程 is present; inspect only small metadata, actual headers validated at import. Unknown names return supported:false for the legacy path.

PhoneStreamingXlsx.importFile(file, {signal, stringStore, onUsers, onRecords, onProgress}) => Promise<{source_format, source_file, source_files, sheet_name, total_records, call_count, data_count, warning_count, date_bounds}>. onUsers(users) and onRecords(records) are awaited batch sinks. Progress receives {stage, processedRows, completedBytes, totalBytes}. Signal uses AbortSignal; throw AbortError on cancellation. Throw a generic row/part diagnostic without cell contents for corrupt structure. stringStore.putMany([{id,value}]) / getMany(ids) => Map<number,string> / clear() are asynchronous, provided by controller's data store. Shared strings must be streamed to this store, looked up in batches with bounded cache, and cleared after import. Never create complete arrays of worksheet/sharedStrings XML or all records. Rich strings and inline strings supported. Physical row numbers and sparse columns retained; Excel numeric dates using styles/1904 epoch and numeric identifiers normalized without locale scientific display. XML input chunks and individual node lengths bounded, parser sink honors backpressure. Reject encrypted/corrupt XLSX safely.

PhoneCdrModel.normalizePhone(value), canonicalHeader(value), normalizeRow(kind, headers, values, {fileName,sheetName,rowNumber,date1904,styles}), normalizeUser(headers,values,context), kindOf(record). normalizeRow returns normalized record or null for blank/header rows. Row has existing standard fields plus record_kind:'call'|'data', source_file/source_sheet/row_number, source_query/source_target and stations:[{station_key,cell_id,address,normalized_address,status,is_virtual}] alongside base_refs. Phone key query item first, then 調閱門號 (call) or 通聯回應_用戶編號_帳號 (data); do not guess from other users. normalizeUser returns {phone,subject,source_file,source_sheet,row_number} or null. Unknown phone stays empty string. Directions inferred relative to target using actual calling field only when decisive, else existing call-type semantics. Network fields include external_ipv4/external_ipv6/internal_ip. Station keys compatible with existing stationKey semantics or self-consistent exact base_refs mapping. No entire raw worksheet row retained, only needed normalized/source fields. Model helper must support both original and previously converted aliases. The importer checks required call/data headers and consumes only the three named source sheets, ignores integrated history. User sheet may be absent, call/data sheet may be absent or empty.
